# tests/unit — Module-level pytest suites

Fast, pure-Python tests, one file per engine module, mirroring the package
tree (`test_storage_ondisk.py`, `test_btree_cursor.py`, `test_parser.py`,
`test_vdbe_builder.py`, …).

## What belongs here (vs the differential corpus)

- Binary-format edges: varints at width boundaries, serial-type round-trips,
  header field packing, checksum vectors.
- State machines: cursor validity across operations, builder label
  backpatching, WAL recovery decision table — including tests that drive
  generators step-by-step through their yield points (the payoff of the
  io-convention; see [../../pyturso/io/README.md](../../pyturso/io/README.md)).
- Property-style tests with fixed seeds: random insert/delete sequences into a
  B-tree asserting order + integrity after every operation (Phase 7's main
  safety net, alongside sqlite3 `integrity_check` in the corpus layer).
- Error paths: corrupt-input fixtures must raise `Corrupt`, never return data.

## What does not belong here

SQL-in/rows-out behavior — that is corpus material
([../differential/README.md](../differential/README.md)); duplicating it here
creates two sources of truth.

## Conventions

- Plain pytest, no plugins; fixtures build DBs via `tools/mkdb.py` scripts.
- AST/EXPLAIN snapshot tests keep snapshots inline (small) or under
  `snapshots/` (large), regenerated by an explicit flag, reviewed in diffs.
